所有商户 API：`POST`、`Content-Type: application/json`、UTF-8。路径接在 base 后，例如 `https://api.at-dev.app/api/v1/player/add`。

## 外层（不加密）

```json
{ "agent_acc": "kiwi01", "data": "<内层加密后的 hex>" }
```

`agent_acc` 英数最长 60。`data` 只含 hex。我们用 `agent_acc` 选 ApiKey。

## 内层（要加密）

```json
{"acc":"jordan","name":"Amy"}
```

字段名 snake_case。这个 JSON 的 UTF-8 bytes 才是明文。

## AES-256-GCM

ApiKey：64 hex → 32 bytes。nonce：**12 bytes，每次请求必须重新随机**。tag：16 bytes。输出顺序：`nonce ‖ ciphertext ‖ tag`，再转 hex。

正式环境禁止重用 nonce。下面测试向量只用固定 nonce 核对实现，**不要当正式密钥**。

<Accordion title="测试向量">
明文必须一字不差：`{"acc":"jordan","name":"Amy"}`

| | hex |
|---|---|
| key | `000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f` |
| nonce | `000102030405060708090a0b` |
| 应得到的 data | `000102030405060708090a0b3c20b778a6c7f839e72ee5efd0875a41a1b8e6599559655e790a9ca760a850743566fe60e4ecf7193d174ad5dd` |
</Accordion>

<CodeGroup>
```javascript Node.js
const crypto = require("crypto");
function encrypt(plain, keyHex) {
  const key = Buffer.from(keyHex, "hex");
  const nonce = crypto.randomBytes(12);
  const cipher = crypto.createCipheriv("aes-256-gcm", key, nonce);
  const enc = Buffer.concat([cipher.update(plain, "utf8"), cipher.final()]);
  return Buffer.concat([nonce, enc, cipher.getAuthTag()]).toString("hex");
}
```

```python Python
import os, binascii
from cryptography.hazmat.primitives.ciphers.aead import AESGCM
def encrypt(plain, key_hex):
    key = binascii.unhexlify(key_hex)
    nonce = os.urandom(12)
    ct = AESGCM(key).encrypt(nonce, plain.encode("utf-8"), None)
    return (nonce + ct).hex()
```
</CodeGroup>

先解析 JSON 再看 `code`。不要 `if (!response.ok) throw` 就结束。

## 信封

```json
{ "api_version": "v1", "message": "", "code": "OK", "data": {}, "trace_id": "uuid" }
```

成功只有 `OK`。`data` 是对象或数组。报障请带 `trace_id`。

| HTTP | 你该做 |
|---|---|
| 200 且 `code=OK` | 成功 |
| 200 且 `code≠OK` | 失败，见 [错误码](/zh-CN/errors) |
| 404 | 路径写错 |
| 500 | **结果不明**。转账 `/transfer/check` |

找不到代理、IP 不在白名单、解密失败、参数不合法：现为 **HTTP 200 + 对应 code**。

单钱包方向相反：我们 POST `{ "data": "<hex>" }`，你回明文 JSON，成功必须 `"OK"`。
