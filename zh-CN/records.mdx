查询接口不变更余额。`end_at` 须大于 `start_at`。`acc` 不含前缀；省略或空字符串表示不筛玩家。成功报文见 [传输协议](/zh-CN/protocol)。`agent`／`member` 同 [转账](/zh-CN/transfer) 页末。

各接口 `start_at`／`end_at` 对应的时间字段：

| 接口 | 对应字段 |
|---|---|
| `/bet_rec/list` | `updated_at`（变动时间，含结算）。另以下注日（`beted_date`，UTC+8 当日 00:00）裁切，须介于区间起日前一天至区间结束日。下注逾一天后才变动的单不在结果内，改用 `/bet_rec/query` 按单号查 |
| `/jp_rec/list` | `created_at` |
| `/bet_report/list` | `beted_date` 或 `settled_date`／分钟字段，值为 UTC+8（`Asia/Shanghai`）当日 00:00 的 Unix 秒 |
| `/scratch_card_rec/list` | `updated_at`（状态变更时间） |
| `/transfer/list` | `created_at` |
| `/free_round/list` | `created_at` |

速率限制见 [G4](/zh-CN/protocol#g4)，保留期限见 [G5](/zh-CN/protocol#g5)。

</Card>

## POST `/bet_rec/query`

<Card title="请求" icon="arrow-up-from-bracket">
| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| `sns` | 是 | string[] | 1–100 个单号 |
</Card>

<Card title="响应" icon="arrow-down-to-bracket">
| 字段 | 类型 | 说明 |
|---|---|---|
| `list` | array | 与请求 `sns` 等长、顺序相同 |

`list[]`：

| 字段 | 类型 | 说明 |
|---|---|---|
| `sn` | string | 查询的单号 |
| `code` | string | 每一列都有。有单为 `OK`，无单为 `BET_NOT_FOUND` |
| `status` | string | 仅当该列 `code` 为 `OK`：[注单状态](/zh-CN/enums#bet-status)。无单时无此字段 |

外层 `code` 为 `OK` 表示本包请求成功。该列 `code` 为 `OK` 才读 `status`。

```json
{
  "code": "OK",
  "data": {
    "list": [
      { "sn": "A", "code": "OK", "status": "PENDING" },
      { "sn": "B", "code": "OK", "status": "FINISH" },
      { "sn": "C", "code": "OK", "status": "REFUND" },
      { "sn": "D", "code": "BET_NOT_FOUND" }
    ]
  }
}
```

列上 `BET_NOT_FOUND` 的处置见 [G3](/zh-CN/protocol#g3)。
</Card>

## 约束 {#constraints}

1. `/bet_report/list` 两个 `time_unit` 母体不同，不得互相加总或对账。
2. 赠送旋转产生的注单仍在 `/bet_rec/list`，`bet_amount` 为名义注额。本接口不另给「是否赠送」字段。
3. 维护中游戏仍出现于 `/game/list`，登录时才返回 `GAME_MAINTAIN`。
