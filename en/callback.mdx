title: Callbacks
description: Platform callbacks. Timeout 15 seconds.
---

Seamless wallet only. The platform `POST`s to `{MerchantApiUrl}{path}`, for example `https://merchant.example/player/bet`.

```json
{ "data": "<AES-GCM hex>" }
```

| Item | Rule |
|---|---|
| `MerchantApiUrl` | Concatenated directly with the path. Must not end with `/` |
| Request body | `data` only. No `agent_acc` |
| Encryption | Same ApiKey and same layout as the merchant API. See [Protocol](/en/protocol) |
| `Content-Type` | `application/json` |
| Timeout | 15 seconds, connect and read included |
| Merchant response | JSON with a top-level `code`. Success is `OK`. Other top-level fields are ignored |
| Merchant HTTP status | Must be 2xx. 4xx is treated as not processed (a `/player/bet` counts as not debited; no `/player/refund` is sent). 5xx and timeouts are treated as undetermined |

Idempotency: [G1](/en/protocol#g1). Resends: [G2](/en/protocol#g2). Undetermined outcome: [G3](/en/protocol#g3).

## POST `{base}/player/bet`

Debit.

<Card title="Request (after decrypt)" icon="arrow-down-to-bracket">
| Field | Type | Description |
|---|---|---|
| `timestamp` | integer | Unix seconds |
| `sn` | string | Idempotency key |
| `game_code` | string | Game code |
| `acc` | string | Player account, without the prefix |
| `name` | string | Display name |
| `amount` | number | Debit amount (positive) |
| `beted_at` | integer | Bet time, Unix seconds |
</Card>

<Card title="Response" icon="arrow-up-from-bracket">
| Field | Type | Description |
|---|---|---|
| `code` | string | `"OK"` on success. `BALANCE_INSUFFICIENT` when the balance is short |
| `data.original_balance` | number | Balance before the debit |
| `data.balance` | number | Balance after the debit |

```json
{
  "code": "OK",
  "data": { "original_balance": 1000, "balance": 900 }
}
```
</Card>

## POST `{base}/player/win`

Credit. `game_code` comes from three sources:

| `game_code` | `sn` shape | Preceding `/player/bet` | Reconcile with |
|---|---|---|---|
| A `/game/list` `code` | Bet id | Yes | `/bet_rec/query` |
| [`TOURNAMENT`](/en/enums#game-code) | `TOUR_{tournament}_{rank}_{member}` | No | No query endpoint. The merchant ledger is authoritative |
| [`SCRATCH_CARD`](/en/enums#game-code) | `SC_{ticket}` | No | [`/scratch_card_rec/list`](/en/records) |

<Card title="Request (after decrypt)" icon="arrow-down-to-bracket">
| Field | Type | Description |
|---|---|---|
| `timestamp` | integer | Unix seconds |
| `sn` | string | Idempotency key |
| `game_code` | string | Game code, [`TOURNAMENT`](/en/enums#game-code) or [`SCRATCH_CARD`](/en/enums#game-code). See the table above |
| `acc` | string | Without the prefix |
| `name` | string | Display name |
| `amount` | number | Credit amount, ≥ 0 (including no win) |
| `beted_at` | integer | Bet time, Unix seconds |
| `settled_at` | integer | Settlement time, Unix seconds |
</Card>

<Card title="Response" icon="arrow-up-from-bracket">
| Field | Type | Description |
|---|---|---|
| `code` | string | `"OK"` |
| `data.original_balance` | number | Balance before the credit |
| `data.balance` | number | Balance after the credit |

```json
{
  "code": "OK",
  "data": { "original_balance": 900, "balance": 1400 }
}
```
</Card>

## POST `{base}/player/refund`

Returns the amount the `/player/bet` with the same `sn` actually debited. The `sn` may never have been debited, so verify before crediting (see [Constraints](#constraints) 2).

<Card title="Request (after decrypt)" icon="arrow-down-to-bracket">
| Field | Type | Description |
|---|---|---|
| `timestamp` | integer | Unix seconds |
| `sn` | string | Id of the matching bet |
| `game_code` | string | Game code |
| `acc` | string | Without the prefix |
| `name` | string | Display name |
| `amount` | number | Refund amount (positive) |
</Card>

<Card title="Response" icon="arrow-up-from-bracket">
| Field | Type | Description |
|---|---|---|
| `code` | string | `"OK"`. An already refunded `sn` also returns `OK`, and the balance does not change |
| `data` | object \| omitted | May be omitted |

```json
{ "code": "OK" }
```
</Card>

## Constraints {#constraints}

1. `TOURNAMENT` and `SCRATCH_CARD` are in neither `/game/list` nor `/bet_rec/query`. They must not be rejected on that basis.
2. `/player/refund`: verify by `sn` that the bet was actually debited. Credit `amount` back only if it was debited and not yet refunded; if it was never debited (bet not received, or rejected with an error `code`) or already refunded, return `OK` and do not credit.
3. Granted-spin consumption sends no `/player/bet`. Settlement may still send `/player/win` (`amount` may be 0). See [Granted spins](/en/free-round).
