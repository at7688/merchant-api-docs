---
title: Callbacks
description: Platform callbacks. Timeout 15 seconds.
---

Seamless wallet only. Platform `POST`s to `{MerchantApiUrl}{path}` (e.g. `https://merchant.example/player/bet`). Base must not end with `/`. Body `{ "data": "<hex>" }` with no `agent_acc`. Same ApiKey. [Protocol](/en/protocol). Timeout 15 seconds. Response JSON must include top-level `code`. bet/win `data.original_balance` and `data.balance` are numbers.

<Warning>
Success: `code` is `OK`.
</Warning>

Timeout 15 seconds. The same packet is not retried immediately. The **same `sn`** may later receive another `/player/win` or `/player/refund` (settle retry, operator resend, stuck-bet refund). Exception: a failed **tournament** payout is not retried automatically and cannot be resent by an operator. Granted-spin consumption does **not** send `/player/bet`; settle may still send `/player/win` (`amount` may be 0). `acc` on bet/win/refund is unprefixed; only the balance callback sends both prefixed `acc` and `player_acc`. Idempotency on `sn`. `/player/win` may arrive after disconnect.

<Warning>
Keep `sn` de-duplication records for **at least 90 days**. Operator resends have no deadline.
</Warning>

## POST `{base}/player/win`

Credit. `game_code` comes from three sources:

| `game_code` | `sn` shape | Preceding `/player/bet` | Reconcile with |
|---|---|---|---|
| a `/game/list` `code` | bet id | yes | `/bet_rec/query` |
| [`TOURNAMENT`](/en/enums#game-code) | `TOUR_{tournament}_{rank}_{member}` | no | no query endpoint; use your own ledger |
| [`SCRATCH_CARD`](/en/enums#game-code) | `SC_{ticket}` | no | [`/scratch_card_rec/list`](/en/records) |

<Warning>
`TOURNAMENT` and `SCRATCH_CARD` are in neither `/game/list` nor `/bet_rec/query`; do not reject them on that basis.
</Warning>

<Card title="Request (after decrypt)" icon="arrow-down-to-bracket">
| Field | Type | Description |
|---|---|---|
| `timestamp` | integer | Unix seconds |
| `sn` | string | Matching bet id |
| `game_code` | string | Game |
| `acc` | string | Unprefixed |
| `name` | string | Display name |
| `amount` | number | Refund (positive) |
</Card>

<Card title="Response" icon="arrow-up-from-bracket">
| Field | Type | Description |
|---|---|---|
| `code` | string | `"OK"` even if already refunded |
| `data` | object \| omitted | May be omitted |
</Card>

<Warning>
`refund` only returns what the `/player/bet` with the same `sn` actually debited. If the merchant never received that bet, or rejected it with an error `code`, it must return `OK` without crediting. The platform sends `refund` as soon as a bet's outcome is unknown, so the bet may never have reached the merchant.
</Warning>

### Retries and deadline

Until it receives `OK`, the platform retries the **same `sn`**: first after 60 seconds, then
exponential backoff (60 × 2^n seconds), capped at 1 hour per interval, with a **24-hour total
deadline**.

After 24 hours retries stop and the refund moves to "overdue", to be resent or closed by an
operator at an unspecified time.
