Query endpoints do not change balances. `end_at` must be greater than `start_at`. `acc` carries no prefix; omitted or empty means no player filter. Success envelope: [Protocol](/en/protocol). `agent` / `member`: end of [Transfers](/en/transfer).

Time column that `start_at` / `end_at` map to, per endpoint:

| Endpoint | Column |
|---|---|
| `/bet_rec/list` | `updated_at` (change time, including settlement). Also pruned by bet date (`beted_date`, UTC+8 00:00), which must fall between the day before the window's start day and the window's end day. A bet that changes more than a day after it was placed is not returned; look it up by `sn` with `/bet_rec/query` |
| `/jp_rec/list` | `created_at` |
| `/bet_report/list` | `beted_date` or `settled_date` / minute column, Unix seconds at UTC+8 (`Asia/Shanghai`) 00:00 |
| `/scratch_card_rec/list` | `updated_at` (status change time) |
| `/transfer/list` | `created_at` |
| `/free_round/list` | `created_at` |

Rate limits: [G4](/en/protocol#g4). Retention: [G5](/en/protocol#g5).

| Field | Type | Description |
|---|---|---|
| `buy_option` | integer | Code of the play mode the player bought this spin (e.g. buy free game, full-board bonus). Absent or `0` = a normal spin or no specific purchase mode. Code meanings vary by game |
| `feature_code` | string | Code of the feature triggered this spin. Absent or empty string = no feature triggered. Code meanings vary by game |

## POST `/bet_rec/query`

<Card title="Request" icon="arrow-up-from-bracket">
| Field | Required | Type | Description |
|---|---|---|---|
| `sns` | yes | string[] | 1–100 bet ids |
</Card>

<Card title="Response" icon="arrow-down-to-bracket">
| Field | Type | Description |
|---|---|---|
| `list` | array | Same length and same order as the request `sns` |

`list[]`:

| Field | Type | Description |
|---|---|---|
| `sn` | string | The bet id queried |
| `code` | string | Present on every item. `OK` when the bet exists, `BET_NOT_FOUND` when it does not |
| `status` | string | Only when the item `code` is `OK`: [bet status](/en/enums#bet-status). Absent when the bet does not exist |

An outer `code` of `OK` means this request succeeded. Read `status` only when the item `code` is `OK`.

```json
{
  "code": "OK",
  "data": {
    "list": [
      { "sn": "A", "code": "OK", "status": "PENDING" },
      { "sn": "B", "code": "OK", "status": "FINISH" },
      { "sn": "C", "code": "OK", "status": "REFUND" },
      { "sn": "D", "code": "BET_NOT_FOUND" }
    ]
  }
}
```

Handling of an item-level `BET_NOT_FOUND`: [G3](/en/protocol#g3).
</Card>

| `time_unit` | Bets counted |
|---|---|
| `bet` | Every bet stored in the period, including unsettled and refunded ones (whose `win_amount` / `result` are 0) |
| `settle` | Settled (`FINISH`) bets only |

| `time_unit` | yes | string | [Time axis](/en/enums#time-unit) |

`list[]`:

## Constraints {#constraints}

1. The two `time_unit` populations of `/bet_report/list` differ. They must not be summed or reconciled against each other.
2. Bets produced by granted spins still appear in `/bet_rec/list`, with `bet_amount` as the nominal stake. This endpoint carries no separate grant flag.
3. Games under maintenance still appear in `/game/list`. Login returns `GAME_MAINTAIN`.
