Seamless wallet: player balance resides with the merchant. The merchant still posts player create and login to the platform. Bet debits and payouts are platform callbacks to the merchant.

Shared spec: [Protocol](/en/protocol), [Error codes](/en/errors). Callback spec: [Callbacks](/en/callback).

## Sequence

1. Obtain `agent_acc` and ApiKey; whitelist source IPs ([G6](/en/protocol#g6)). Provide the merchant callback base URL (must not end with `/`); the platform configures it per `agent_acc`.
2. Implement encryption for merchant → platform, and decryption for platform → merchant callbacks. Same key.
3. `POST /player/add`, `POST /player/login`. `acc` excludes the agent prefix.
4. Implement the callbacks: `/player/balance`, `/player/bet`, `/player/win`, `/player/refund`.
5. De-duplicate idempotently per [G1](/en/protocol#g1). The platform may also re-send callbacks for the same `sn` (e.g. a refund after an undecided bet, or a win resend), which you must accept ([G2](/en/protocol#g2)).
6. Reconciliation: `/bet_rec/query` covers bets only. An `sn` starting with `SC_` (scratch-card payout) uses `/scratch_card_rec/list`; one starting with `TOUR_` (tournament payout) has no query endpoint — use your own ledger.
