title: Transfers
description: Credit and debit. sn must be unique.
---

**Transfer wallet only.** Treat `sn` like a bank reference: one business event, one `sn`. We use it so retries are not double-posted.

| | Rules |
|---|---|
| `sn` | alphanum plus `_` `-`, 6–120 |
| `acc` | player id, no prefix |
| `amount` | ≠ 0. Positive = credit to platform; negative = debit from platform |
| time | Unix **seconds** |

## POST `/transfer/add`

Credit 100:

```json
{ "sn": "T20260917-0001", "acc": "jordan", "amount": 100 }
```

Debit 50: `"amount": -50`.

Success: `{ "code": "OK", "data": { "currency": "TWD", "balance": 100 } }` (`balance` after this transfer).

<Steps>
  <Step title="code = OK">
    Posted. Never reuse this `sn`.
  </Step>
  <Step title="TRANSFER_SN_EXIST">
    Already posted. `/transfer/check`. Do **not** create a new sn.
  </Step>
  <Step title="BALANCE_INSUFFICIENT">
    Debit failed. New sn when the player has funds.
  </Step>
  <Step title="HTTP 500 / disconnect">
    Unknown. `/transfer/check` with the **same** sn. Found → done. `TRANSFER_NOT_FOUND` → then a new sn is safe.
  </Step>
</Steps>

<Warning>
Do not immediately retry with a new `sn` after HTTP 500. That double-credits the player.
</Warning>

## POST `/transfer/check`

```json
{ "sn": "T20260917-0001", "acc": "jordan" }
```

Missing → `TRANSFER_NOT_FOUND`.

## POST `/transfer/list`

10 calls / merchant / minute. `page` ≥ 1, `perpage` 1–100, `start_at` / `end_at` required (`end_at` > `start_at`), `acc` optional.
