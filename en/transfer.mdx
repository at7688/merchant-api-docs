---
title: Transfers
description: Transfer-wallet credit and debit.
---

Transfer wallet only. `sn` is the idempotency key: one business event maps to one `sn`.

| Field | Constraints |
|---|---|
| `sn` | alphanum plus `_` `-`, 6–120 |
| `acc` | player id, no prefix |
| `amount` | ≠ 0. Positive = credit to platform; negative = debit from platform |
| time | Unix seconds |

## POST `/transfer/add`

```json
{ "sn": "T20260917-0001", "acc": "jordan", "amount": 100 }
```

Debit example: `"amount": -50`.

```json
{ "code": "OK", "data": { "currency": "TWD", "balance": 100 } }
```

`balance` is the platform balance after this transfer.

| code | Meaning | Handling |
|---|---|---|
| `OK` | Posted | Do not reuse `sn` |
| `TRANSFER_SN_EXIST` | `sn` already posted | `/transfer/check`. Not a failure |
| `BALANCE_INSUFFICIENT` | Debit exceeds balance | Not posted |
| `ACC_NOT_FOUND` | Player missing | Not posted |

HTTP 500 or a dropped connection is undetermined. `/transfer/check` with the **original** `sn`: a row means posted; `TRANSFER_NOT_FOUND` allows a new `sn`. Replacing `sn` immediately after 500 can double-post.

## POST `/transfer/check`

```json
{ "sn": "T20260917-0001", "acc": "jordan" }
```

Missing record: `TRANSFER_NOT_FOUND`.

## POST `/transfer/list`

Rate: 10 calls per merchant per minute.

| Field | Required | Constraints |
|---|---|---|
| `page` | yes | ≥ 1 |
| `perpage` | yes | 1–100 |
| `start_at` | yes | Unix seconds |
| `end_at` | yes | greater than `start_at` |
| `acc` | no | |

`data`: `list`, `row_count`, `page_count`.
