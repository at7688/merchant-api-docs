## Request

| Item | Rule |
|---|---|
| Method | `POST` |
| Header | `Content-Type: application/json` |
| Encoding | UTF-8 |
| URL | `{base}{path}` |
| Path prefix | `/api/v1` |
| Extra headers | None. Client IP is `CF-Connecting-IP`, else `X-Forwarded-For` / peer, and must be whitelisted |

## Conventions

| Item | Rule |
|---|---|
| `agent_acc` | Trimmed, lowercased |
| `acc` | Trimmed, lowercased, stored as `{agent_acc}_{acc}` |
| `game_code` | Trimmed, uppercased |
| Time | Unix **seconds**. Accounting day cut is **UTC+8** (`Asia/Taipei`) 00:00 |
| Amounts | JSON numbers, up to 2 decimal places |
| Optional filters | Empty string or 0 means “do not apply” |
| Validation failure | `code` `PARAM_INVALID` |

Callback URL is `{MerchantApiUrl}/player/bet`. The base must **not** end with `/`.

### Outer body

```json
{
  "agent_acc": "kiwi01",
  "data": "<ciphertext hex>"
}
```

| Field | Required | Type | Constraints |
|---|---|---|---|
| `agent_acc` | yes | string | alphanum, ≤ 60 |
| `data` | yes | string | hex of the encrypted inner JSON |

### Inner body

UTF-8 JSON object, snake_case. Those bytes are the GCM plaintext.

```json
{"acc":"jordan","name":"Amy"}
```

## AES-256-GCM

| Parameter | Value |
|---|---|
| Algorithm | AES-256-GCM |
| Key | ApiKey decoded from hex, 32 bytes |
| nonce | 12 bytes, unique per request |
| tag | 16 bytes |
| Layout | `nonce ‖ ciphertext ‖ tag`, then hex |

Seamless-wallet callbacks use the same key and layout. The platform body is only `{ "data": "<hex>" }` — no `agent_acc`. Timeout 15 seconds. The merchant response must be JSON with top-level `code`. HTTP status must be 2xx or the outcome is treated as undetermined.

### Reference vector

Verification only — not a production key. Plaintext `{"acc":"jordan","name":"Amy"}` with no whitespace.

| | hex |
|---|---|

<CodeGroup>
```javascript Node.js
const crypto = require("crypto");

function encrypt(plain, keyHex) {
  const key = Buffer.from(keyHex, "hex");
  const nonce = crypto.randomBytes(12);
  const cipher = crypto.createCipheriv("aes-256-gcm", key, nonce);
  const enc = Buffer.concat([cipher.update(plain, "utf8"), cipher.final()]);
  return Buffer.concat([nonce, enc, cipher.getAuthTag()]).toString("hex");
}
```

```python Python
import os, binascii
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

def encrypt(plain: str, key_hex: str) -> str:
    key = binascii.unhexlify(key_hex)
    nonce = os.urandom(12)
    ct = AESGCM(key).encrypt(nonce, plain.encode("utf-8"), None)
    return (nonce + ct).hex()
```

## Response

All successful merchant APIs use this envelope. Per-endpoint `data` fields are on each page.

```json
{
  "api_version": "v1",
  "message": "",
  "code": "OK",
  "data": {},
  "trace_id": "3f2c1a0b-...."
}
```

| Field | Type | Description |
|---|---|---|
| `api_version` | string | Currently `v1` |
| `message` | string | Extra text; usually empty |
| `code` | string | Outcome. Success is only `OK` |
| `data` | object \| array \| null | Payload on success; usually `null` on error |
| `trace_id` | string | Request id for logs and incidents |

Outcome is `code`.

Unknown path: HTTP 404. HTTP 500 means the outcome is undetermined; the body may not be JSON. Transfers: `/transfer/check` with the same `sn`. Seamless: merchant ledger and `/bet_rec/query`. Reversals must not be assumed.
