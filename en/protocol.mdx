## Request

| Item | Rule |
|---|---|
| Method | `POST` |
| Header | `Content-Type: application/json` |
| Encoding | UTF-8 |
| URL | `{base}{path}`, e.g. `https://api.at-dev.app/api/v1/player/add` |
| Path prefix | `/api/v1` |
| Extra headers | None. Client IP is `CF-Connecting-IP`, else `X-Forwarded-For` / peer, and must satisfy [G6](#g6) |

## Conventions

| Item | Rule |
|---|---|
| `agent_acc` | Lowercased and trimmed before matching |
| `acc` | Trimmed, lowercased, then combined with the agent account as `{agent_acc}_{acc}` |
| `game_code` | Trimmed and uppercased. Applies to login and granted spins |
| Time | Unix seconds (10 digits). The accounting day cut is UTC+8 (`Asia/Shanghai`) 00:00 |
| Amounts | JSON number (database `DECIMAL`). Amounts you send: up to 2 decimal places. Amounts in our callbacks: up to 4 decimal places (slot wins, and debits multiplied by a buy multiplier, can have 3 or 4) |
| Optional filters | Empty string or 0 means the condition is not applied |
| Malformed request | Outer or inner JSON unparseable, wrong field type, or failed validation — all return `PARAM_INVALID` |

### Outer body

```json
{
  "agent_acc": "kiwi01",
  "data": "<ciphertext hex>"
}
```

| Field | Required | Type | Constraints |
|---|---|---|---|
| `agent_acc` | yes | string | alphanumeric, ≤ 60, matching a back-office agent account |
| `data` | yes | string | hex of the encrypted inner plaintext |

### Inner body

UTF-8 JSON object, fields in snake_case. Those bytes are the GCM plaintext. Example:

```json
{"acc":"jordan","name":"Amy"}
```

## AES-256-GCM

| Parameter | Value |
|---|---|
| Algorithm | AES-256-GCM |
| Key | ApiKey decoded from hex, 32 bytes |
| nonce | 12 bytes, random per request, never reused |
| tag | 16 bytes |
| Layout | `nonce ‖ ciphertext ‖ tag`, then hex |

Seamless-wallet callbacks use the same key and the same layout. The envelope is on [callbacks](/en/callback).

### Reference vector {#vectors}

The plaintext is `{"acc":"jordan","name":"Amy"}` with no whitespace and no newlines. It is the inner body of `/player/add`, not a callback sample.

| | hex |
|---|---|
| key | `000102030405060708090a0b0c0d0e0f101112131415161718191a1b1c1d1e1f` |
| nonce | `000102030405060708090a0b` |
| data | `000102030405060708090a0b3c20b778a6c7f839e72ee5efd0875a41a1b8e6599559655e790a9ca760a850743566fe60e4ecf7193d174ad5dd` |

<CodeGroup>
```javascript Node.js
const crypto = require("crypto");

function encrypt(plain, keyHex) {
  const key = Buffer.from(keyHex, "hex");
  const nonce = crypto.randomBytes(12);
  const cipher = crypto.createCipheriv("aes-256-gcm", key, nonce);
  const enc = Buffer.concat([cipher.update(plain, "utf8"), cipher.final()]);
  return Buffer.concat([nonce, enc, cipher.getAuthTag()]).toString("hex");
}
```

```python Python
import os, binascii
from cryptography.hazmat.primitives.ciphers.aead import AESGCM

def encrypt(plain: str, key_hex: str) -> str:
    key = binascii.unhexlify(key_hex)
    nonce = os.urandom(12)
    ct = AESGCM(key).encrypt(nonce, plain.encode("utf-8"), None)
    return (nonce + ct).hex()
```
</CodeGroup>

## Response

Every endpoint returns this envelope on success. The `data` fields are on each endpoint page.

```json
{
  "api_version": "v1",
  "message": "",
  "code": "OK",
  "data": {},
  "trace_id": "3f2c1a0b-...."
}
```

| Field | Type | Description |
|---|---|---|
| `api_version` | string | API version, currently `v1` |
| `message` | string | Extra text; usually empty |
| `code` | string | Business outcome. Success is only `OK` |
| `data` | object \| array \| null | Payload on success. Usually `null` on error; a few errors carry a diagnostic object (see [error codes](/en/errors)) |
| `trace_id` | string | Request id, used for reconciliation and incident reports |

The outcome is `code`. Every `code`, `PARAM_INVALID` and `TOO_MANY_REQUESTS` included, is returned with HTTP 200.

### HTTP status

| Status | Meaning |
|---|---|
| `200` | The request was processed. Read `code` for the outcome |
| `404` | Unknown path |
| `500` | Outcome undetermined; the body may not be JSON. Handling is in [G3](#g3) |

## General rules

These six rules span multiple endpoints. Endpoint pages cite them by number.

### G1 Idempotency key {#g1}

Platform API (`/transfer/add`, `/free_round/add`):

| Item | Rule |
|---|---|
| Key | `sn` |
| First receipt | Executed, and the result persisted |
| Duplicate, first attempt succeeded | The first result is returned; the balance does not change |
| Duplicate, first attempt rejected | The first error `code` is returned |

Seamless-wallet callbacks (`/player/bet`, `/player/win`, `/player/refund`):

| Item | Rule |
|---|---|
| Key | Callback path + `sn` |
| Same `sn` across paths | `/player/win` and `/player/refund` reuse the `sn` of the round's `/player/bet`. `/player/bet` followed by `/player/win` or `/player/refund` on the same `sn` is the normal flow, not a duplicate |
| Duplicate, previously processed successfully | Return `OK`; the balance does not change |
| Duplicate, not previously processed successfully (a non-`OK` was returned) | Treat it as a new request; the merchant decides from the current state whether to process it. Return `OK` if processed successfully |
| Non-`OK` | A non-`OK` must not be returned merely because the request is a duplicate. The platform treats any non-`OK` as a failure |
| Merchant de-duplication records | Kept at least 90 days |

### G2 Callback resends {#g2}

The same packet is not resent at the moment of a timeout. The same `sn` may receive a later callback:

| Case | Later callback |
|---|---|
| `/player/bet` outcome undetermined | `/player/refund` (automatic or operator resend) |
| `/player/win` did not succeed (ordinary bet) | Another `/player/win` (game retry or operator resend) |
| `/player/win` did not succeed (tournament payout) | No automatic resend; an operator resends it |
| `/player/win` did not succeed (scratch-card payout) | No automatic resend. The ticket reverts to claimed, not scratched ([`CLAIMED`](/en/enums#scratch-status)); when the player scratches it again, `/player/win` is sent again with the same `sn` |
| Stuck bet cancelled after timeout | `/player/refund` |

Automatic resends of `/player/refund`:

| Item | Rule |
|---|---|
| First send | For an undetermined `/player/bet`, about 2 to 3 minutes after the outcome became undetermined; for a stuck bet cancelled after timeout, within about 1 minute of the cancellation |
| Backoff | After each unsuccessful attempt, intervals of 60, 120, 240 seconds… (60 × 2^n seconds); one interval capped at 1 hour |
| Total window | 24 hours |
| After 24 hours | Automatic resends stop and the item becomes pending-overdue; an operator resends it or closes it manually, with no deadline |

`/player/win` may arrive after the player goes offline.

### G3 Undetermined outcome {#g3}

HTTP 500, a dropped connection or a timeout: success or failure must not be assumed, and a reversal must not be posted.

| Context | Rule |
|---|---|
| `/transfer/add` | Call `/transfer/check` with the original `sn`. A row means it is posted; a new `sn` is allowed only after `TRANSFER_NOT_FOUND` |
| Seamless | The merchant ledger for that `sn` is authoritative, reconciled with `/bet_rec/query` |
| Other endpoints | Retries may reuse the original parameters |

A `BET_NOT_FOUND` item in `/bet_rec/query` must not trigger an automatic refund. A transfer `sn` must not be replaced.

### G4 Rate limits {#g4}

| Endpoint | Limit |
|---|---|
| `/bet_rec/list`, `/jp_rec/list`, `/bet_report/list`, `/scratch_card_rec/list` | 10 per merchant per minute |
| Other endpoints | Not rate limited |

Exceeding the limit returns `TOO_MANY_REQUESTS`.

### G5 Data retention {#g5}

| Subject | Period |
|---|---|
| Bets (`/bet_rec/list`, `/bet_rec/query`) | 60 days. Expired bets are removed: `/bet_rec/list` returns an empty list, `/bet_rec/query` returns `BET_NOT_FOUND` for that row |
| Aggregates (`/bet_report/list`) | 60 days. An earlier window returns an empty list (`code` is `OK`, `row_count` is 0) |
| Transfers (`/transfer/list`) | 60 days |
| JP (`/jp_rec/list`), scratch cards (`/scratch_card_rec/list`), granted-spin records (`/free_round/list`) | No fixed limit; not currently pruned |
| Merchant-side `sn` de-duplication records | At least 90 days |
| Granted spins with no `expire_at` | 30 days from the grant |

### G6 Key and source address {#g6}

| Item | Rule |
|---|---|
| ApiKey | Server-side only |
| Reference vector key | Not usable as a production key |
| Source IP | Must be on the merchant whitelist, otherwise `IP_NOT_ALLOWED` is returned |
| Whitelist matching | Exact match per IP address; ranges and CIDR are not supported. Each egress address is registered individually, including every address in a NAT pool |
| IPv6 | Must be literally identical to the source address |
| Incident reports | Provide the environment, path, `agent_acc`, `trace_id` and UTC time, without the ApiKey |
