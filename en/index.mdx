The AT Gaming merchant API covers player accounts, funds, game entry, and reporting. All calls are `HTTPS` `POST` with `Content-Type: application/json; charset=utf-8`. Inner parameters are AES-256-GCM encrypted into outer `data`. See [Protocol](/en/protocol).

Select a wallet model. Encryption and the response envelope are shared; funding interfaces differ.

## Environments

| Environment | Base URL |
|---|---|
| Test | `https://api.at-dev.app/api/v1` |
| Production | `https://api.at-gaming.app/api/v1` |

Source IPs must appear on the merchant whitelist or the response is `IP_NOT_ALLOWED`.

## Credentials

| Field | Description |
|---|---|
| `agent_acc` | Merchant agent account. Outer body, not encrypted |
| ApiKey | 64 hex characters (32 bytes) for inner encrypt/decrypt |

The ApiKey must remain server-side. Incident reports include environment, path, `agent_acc`, `trace_id`, and UTC time — never the ApiKey.

## Accounts

Inner `acc` is the player identifier without the agent prefix. Stored as `{agent_acc}_{acc}` (e.g. `kiwi01_jordan`).

| Direction | Field | Example |
|---|---|---|
| Merchant → platform | `acc` | `jordan` |
| Platform → merchant (balance callback) | `acc` | `kiwi01_jordan` |
| Platform → merchant (balance callback) | `player_acc` | `jordan` |
| Platform → merchant (bet / win / refund) | `acc` | `jordan` |

A duplicated prefix yields `ACC_NOT_FOUND`.

## Success

A call succeeds only when JSON `code` equals the string `OK`. HTTP status and `"200"` are not success criteria. See [Error codes](/en/errors).
