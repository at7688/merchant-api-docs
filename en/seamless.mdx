For **seamless** merchants only.

We POST `{ "data": "<AES-GCM hex>" }` to your base URL. Decrypt with the **same** ApiKey.

<Warning>
Success = HTTP 200 and `"code": "OK"` (string). `"200"`, `200`, or `"success"` are treated as failures.
</Warning>

| Path | When | You do |
|---|---|---|
| `/player/balance` | Enter game / refresh | Return balance |
| `/player/bet` | Place bet | **Debit**, unique on `sn` |
| `/player/win` | Settle | **Credit**, unique on `sn` |
| `/player/bet_refund` | Bet cannot complete | **Refund that bet**, unique on `sn` |

Timeout **15 seconds**. We do not immediately resend the same packet; an unknown debit may be followed by `bet_refund`. Always respond within 15s.

## Dedupe

1. New `sn` → apply, store result, return `OK`
2. Same `sn`, previous success → return the **same** body, do not change balance
3. Same `sn`, previous reject → return the same error `code`

Players may disconnect before `win`. Still accept it.

## POST `{base}/player/balance`

```json
{ "timestamp": 1758723906, "acc": "kiwi01_jordan", "player_acc": "jordan" }
```

`acc` is prefixed; `player_acc` is not. Success: `{ "code": "OK", "data": { "balance": 1680.4 } }`.

## POST `{base}/player/bet`

```json
{
  "timestamp": 1758723906,
  "sn": "SGP2504300009402",
  "game_code": "MLCQ",
  "acc": "jordan",
  "name": "Amy",
  "amount": 100,
  "beted_at": 1758723906
}
```

Here `acc` has **no** prefix. Success `data`: `original_balance` (before debit), `balance` (after). Insufficient funds: HTTP 200 + `BALANCE_INSUFFICIENT`.

## POST `{base}/player/win`

This **credits**. Tournament payouts use `game_code` `TOURNAMENT`. Include `beted_at` and `settled_at`.

## POST `{base}/player/bet_refund`

Refund the matching bet `sn`. If already refunded, return `OK` and do not credit again.

## Checklist

- [ ] Same `sn` on bet twice → one debit
- [ ] Same `sn` on win twice → one credit
- [ ] `"OK"` not `"200"`
- [ ] Respond within 15s
- [ ] Accept win after disconnect
