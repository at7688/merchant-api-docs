title: 錯誤碼表
description: 成功值僅為 OK。
---

`code` 等於 `OK` 表示成功，其餘值表示失敗。`data` 於多數錯誤為 `null`。

`ACC_NOT_ACTIVE`、`ACC_SUSPEND` 兩張表皆有，以 `data` 區分：商戶層帶 `agent` 物件，玩家層為 `null`（僅 `/player/login`）。

## 傳輸與鑑權

| code | 定義 | 後續 |
|---|---|---|
| `AGENT_NOT_FOUND` | 外層 `agent_acc` 無法對應代理 | |
| `IP_NOT_ALLOWED` | 來源 IP 不在白名單，見 [G6](/protocol#g6) | |
| `API_KEY_INVALID` | ApiKey 未設定或長度非 32 位元組 | |
| `DATA_FORMAT_INVALID` | `data` 非合法 hex | |
| `DECRYPT_FAILED` | 解密失敗 | |
| `PARAM_INVALID` | 請求不合格：外層或內層 JSON 無法解析、欄位型別不對、或欄位驗證未通過 | |
| `IP_BLOCKED` | 來源 IP 或國家被封鎖 | |
| `ACC_NOT_ACTIVE` | 商戶未啟用。`data` 帶 `{agent, status}` | 終止呼叫 |
| `ACC_SUSPEND` | 商戶已暫停。`data` 帶 `{agent, current_status}` | 終止呼叫 |
| `TOO_MANY_REQUESTS` | 超過速率，上限見 [G4](/protocol#g4) | |
| `INTERNAL_SERVER_ERROR` | 系統錯誤，伴隨 HTTP 500。可能發生在業務邏輯執行中 | 見 [G3](/protocol#g3) |

除 `INTERNAL_SERVER_ERROR` 外，上述錯誤在請求進入業務邏輯前發生，重試得使用原參數。

## 業務

| code | 定義 | 後續 |
|---|---|---|
| `ACC_EXIST` | 玩家帳號已存在。視為已建立 | |
| `ACC_NOT_FOUND` | 玩家不存在 | 呼叫 `/player/add` |
| `ACC_NOT_ACTIVE` | 玩家未啟用。`data` 為 `null` | 拒絕進入遊戲 |
| `ACC_SUSPEND` | 玩家已暫停。`data` 為 `null` | 拒絕進入遊戲 |
| `BALANCE_INSUFFICIENT` | 餘額不足 | 單錢包 `bet`：以此 `code` 回應平台 |
| `TRANSFER_SN_EXIST` | `sn` 已成功入帳。非失敗 | 呼叫 `/transfer/check` |
| `TRANSFER_NOT_FOUND` | 無此轉帳 | 見 [G3](/protocol#g3) |
| `GAME_NOT_FOUND` | 遊戲代碼無效 | 以 `/game/list` 核對 |
| `BET_NOT_FOUND` | `/bet_rec/query` 該列查無此單。外層 `code` 仍為 `OK`。`TOUR_`／`SC_` 開頭者不在注單內，見 [回調](/callback) | 見 [G3](/protocol#g3) |
| `GAME_MAINTAIN` | 遊戲或類別維護中 | |
| `BET_AMOUNT_RANGE` | 注額超出該玩家該遊戲上下限 | |
| `FREE_ROUND_CAP` | 超過商戶當月贈送名目總額 | 不得重送同一批 |
| `WRONG_OPERATION` | 參數無法發放贈送旋轉 | |
